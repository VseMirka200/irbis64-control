# Архитектура проекта

Проект разделён по ответственности: интерфейс управляет пользовательскими сценариями, слой приложения хранит настройки и обновления, ядро сопоставляет записи, отчёты отвечают за экспорт, инфраструктура работает с файлами и сервером ИРБИС64.

## Направление зависимостей

```text
точки запуска
      │
      ▼
     ui ─────────► application
      │                 │
      ├─────────────► core
      ├─────────────► reporting
      └─────────────► infrastructure
                           ▲
core ──────────────────────┘
reporting ───────► core + infrastructure
application ─────► core + infrastructure
```

Модули `core` не импортируют интерфейс. Фоновые операции находятся в `ui/services/workers.py`, а окна — в `ui/windows`, поэтому элементы интерфейса отделены от сетевой и файловой обработки. Модели вынесены из алгоритмов, чтобы их можно было использовать в тестах и новых сценариях без импорта крупных модулей.

В корне оставлены только точки запуска. Старые импорты окон поддерживают небольшие совместимые модули `ui/main_window.py` и `ui/db_connector_window.py`. Новый код должен импортировать окна из `irbis_control.ui.windows`.

## Правила размещения нового кода

- модели данных размещаются рядом с предметной областью в `models.py`;
- вычисления и правила сопоставления находятся в `core`;
- чтение и запись внешних форматов находятся в `infrastructure` или `reporting`;
- настройки и обновления находятся в `application`;
- виджеты не должны содержать алгоритмы сопоставления или реализацию протокола ИРБИС64;
- новый корневой Python-файл добавляется только для отдельной точки запуска.
