# Архитектура проекта

Документ описывает структуру «ИРБИС64 Контроль» версии **0.1.0**.

## Общая схема

Приложение разделено на четыре слоя:

~~~text
UI (PyQt6)
  ↓
Application (настройки, обновления)
  ↓
Core / Reporting (модели, сопоставление, метки, отчёты)
  ↓
Infrastructure (Excel, TXT, сеть ИРБИС64, НКП, атомарная запись)
~~~

Слой интерфейса собирает параметры и запускает фоновые операции. Бизнес-логика не зависит от виджетов и может проверяться обычными модульными тестами. Инфраструктурный слой изолирует файловые форматы и внешние системы.

## Точки входа

- **main.py** — совместимая точка запуска основного окна;
- **python -m irbis_control** — пакетная точка запуска того же окна;
- **db_connector.py** — отдельный инструмент обмена между ИРБИС64 и TXT;
- **scripts/build_exe.bat** — локальная сборка двух EXE через PyInstaller;
- **scripts/build_installer.bat** — сборка EXE и Windows-установщика через Inno Setup 6;
- **installer/IRBIS64Control.iss** — описание установки, ярлыков и удаления программы;
- **start_irbis64-control.bat** — подготовка окружения и запуск из исходников.

main.py и db_connector.py намеренно остаются тонкими оболочками: их используют PyInstaller, документация и внешние сценарии.

## Структура пакета

### irbis_control/core

Чистая прикладная логика:

- **models.py** — записи базы, строки Excel, записи иноагентов, результаты и сводки;
- **text.py** — безопасное преобразование и нормализация текста;
- **matcher.py** — чтение источников, нормализация ISBN, правила и движок сопоставления;
- **matching_engine.py** — индексирование и поиск кандидатов;
- **manual_review_memory.py** — устойчивые ключи ручных решений и их хранение;
- **marker_updates.py** — построение, добавление, удаление и дедупликация меток;
- **report_export.py** — формирование итоговой книги Excel.

Core не должен импортировать PyQt6.

### irbis_control/application

Сценарии и сохраняемые настройки:

- **settings.py** — общие настройки приложения и схема JSON;
- **marker_settings.py** — правила, формат отчёта и служебные метки;
- **updater.py** — получение сведений о релизе, проверка источника и контрольной суммы, подготовка обновления.

### irbis_control/infrastructure

Работа с внешними форматами и сервисами:

- **atomic_io.py** — запись через временный файл с атомарной заменой;
- **excel_io.py** — централизованное открытие книг Excel;
- **irbis_client.py** — сетевой протокол ИРБИС64;
- **irbis_models.py** — модели соединения, записи и снимка;
- **irbis_bridge.py** — создание TXT-снимка, карта MFN и безопасная обратная запись;
- **nkp_source.py** — загрузка, проверка и кэширование реестров НКП РГБ.

### irbis_control/reporting

Сравнение результатов:

- **models.py** — строки и сводки различий;
- **result_diff.py** — сравнение Excel-отчётов и TXT-баз, экспорт изменений.

### irbis_control/ui

Интерфейс PyQt6:

- **windows/main.py** — состояние главного окна и общие настройки;
- **windows/main_build.py** — создание исходного набора виджетов;
- **windows/main_layout.py** — компоновка текущего рабочего сценария;
- **windows/main_run.py** — валидация ввода, запуск проверки и обработка результата;
- **windows/main_operations.py** — подключение, запись, обслуживание и обновления;
- **windows/connection_dialog.py** — параметры сервера ИРБИС64;
- **windows/database_connector.py** — отдельный инструмент TXT-обмена;
- **components/** — переиспользуемые виджеты и диалоги;
- **services/workers.py** — фоновые QObject-работники;
- **theme.py**, **locale.py**, **message_box.py** — оформление и платформенная интеграция.

ui/main_window.py и ui/db_connector_window.py являются совместимыми публичными импортами и не должны удаляться без миграционного периода.

## Поток основной проверки

1. UI проверяет выбранные пути, режим результата и параметры подключения.
2. При использовании НКП работник получает актуальный файл или выбирает проверенный кэш.
3. Для прямого режима записи читаются с сервера пакетами и преобразуются во внутренние модели. Для TXT записи разбираются локально.
4. Excel-строки нормализуются и сопоставляются с индексами записей базы.
5. Надёжные совпадения подтверждаются автоматически; конфликтующие передаются в диалог ручной проверки.
6. Решения пользователя сохраняются в памяти и применяются к идентичному контексту в следующих запусках.
7. В зависимости от режима создаётся Excel-отчёт, TXT-копия с метками или план прямой записи.
8. Перед записью на сервер выполняется повторное чтение и контроль версии. Изменившиеся записи пропускаются.

Долгие операции выполняются в рабочих объектах, перемещённых в QThread. UI получает прогресс, завершение, отмену и ошибки через сигналы Qt.

## Форматы и совместимость

### Excel

Новые книги читаются через openpyxl, старые .xls — через xlrd. Заголовки нормализуются и сопоставляются со словарями синонимов. Выходные книги создаются в .xlsx.

### TXT ИРБИС

Запись состоит из строк «#тег: значение»; граница записей определяется форматом выгрузки. При создании снимка сохраняется JSON-карта, связывающая локальную позицию с MFN и хешем серверной версии.

### Настройки

JSON-настройки находятся в пользовательских каталогах, которые возвращает QStandardPaths. Файлы включают:

- application_settings.json;
- marker_settings.json;
- window_state.json;
- database_connector.json;
- manual_review_confirmations.json;
- run_journal.log;
- кэш и метаданные реестров НКП.

Записываемые программой конфигурации используют UTF-8. Критичные замены выполняются атомарно.

## Инварианты безопасности

- исходная локальная TXT-база не изменяется основным окном;
- прямое изменение возможно только после явного подтверждения;
- серверная версия проверяется непосредственно перед записью;
- rollback-копия включена по умолчанию;
- запись меток идемпотентна и исправляет собственные дубли;
- очистка ограничена известными стандартными и пользовательскими метками;
- URL обновлений принимаются только по HTTPS с доверенных доменов GitHub;
- размер и доступный SHA-256 загруженного обновления проверяются до установки.

Изменения этих правил требуют отдельных тестов и явного описания риска в Pull Request.

## Тестирование

Тесты повторяют структуру пакета:

- **tests/core** — нормализация, границы сопоставления, память решений и метки;
- **tests/application** — настройки и обновления;
- **tests/infrastructure** — атомарные операции, НКП и сетевые повторы;
- **tests/reporting** — отчёты и сравнение;
- **tests/ui** — состояние и ключевые сценарии интерфейса.

CI запускается на Windows для Python 3.11 и 3.13 и выполняет Ruff, проверку форматирования, компиляцию модулей и unittest. Оконные тесты выполняются в отдельных процессах: это не позволяет внутреннему состоянию Qt накапливаться между окнами и завершать весь набор без Python-ошибки.

## Выпуски

Workflow выпуска запускается тегом `0.1.0`/`v0.1.0` или вручную. Версия тега должна совпадать с `project.version` в `pyproject.toml`. GitHub Actions:

1. собирает основное приложение и коннектор через PyInstaller;
2. создаёт установщик Inno Setup для установки без прав администратора;
3. помещает оба EXE в ZIP-архив для переносного запуска;
4. рассчитывает SHA256SUMS.txt для установщика и ZIP-архива;
5. создаёт GitHub Release.

Номер версии также экспортируется как irbis_control.__version__; при изменении версии эти значения должны оставаться синхронными.

## Правила развития архитектуры

- бизнес-правила размещаются в Core, а не в обработчиках виджетов;
- файловая и сетевая работа остаётся в Infrastructure;
- длительные действия не выполняются в главном потоке Qt;
- новые настройки должны иметь безопасное значение по умолчанию и терпимо читать старые JSON;
- публичные совместимые импорты и форматы отчётов изменяются только с миграцией;
- для любой операции записи предусматриваются предварительный просмотр, журналирование или восстановление соразмерно риску.
