# Архитектура проекта

## Направление зависимостей

```text
точки запуска
      │
      ▼
     ui ─────────► application
      │                 │
      ├─────────────► core
      ├─────────────► reporting
      └─────────────► infrastructure
                           ▲
core ──────────────────────┘
reporting ───────► core + infrastructure
application ─────► core + infrastructure
```

Модули `core` не импортируют интерфейс. Фоновые операции находятся в `ui/workers.py`, поэтому главное окно не содержит сетевую и файловую обработку. Модели отделены от алгоритмов, чтобы их можно было использовать в тестах и новых сценариях без импорта крупных модулей.

Файлы в корне с именами модулей оставлены только для обратной совместимости. Новый код должен импортировать модули из пакета `irbis_control`.

## Правила размещения нового кода

- модели данных размещаются рядом с предметной областью в `models.py`;
- вычисления и правила сопоставления находятся в `core`;
- чтение и запись внешних форматов находятся в `infrastructure` или `reporting`;
- настройки и обновления находятся в `application`;
- виджеты не должны содержать алгоритмы сопоставления или реализацию протокола ИРБИС64;
- новый корневой Python-файл добавляется только для совместимости или отдельной точки запуска.
